# Production Deployment Checklist

Используйте этот чеклист перед развертыванием приложения на production сервере.

## 📋 Подготовка

### Сервер
- [ ] Выбран подходящий сервер (минимум 512MB RAM, 1 CPU core)
- [ ] Установлена ОС (рекомендуется Ubuntu 22.04 LTS или выше)
- [ ] Настроен SSH доступ
- [ ] Настроен firewall (UFW/iptables)
- [ ] Установлен Docker и Docker Compose (если используется)
- [ ] Настроено доменное имя (если требуется)

### Код
- [ ] Последняя версия кода из репозитория
- [ ] Все зависимости установлены и актуальны
- [ ] Проект успешно собирается локально (`npm run build`)
- [ ] Все тесты пройдены (если есть)
- [ ] Проверен linting (`npm run lint`)

### Конфигурация
- [ ] Создан `.env` файл с production значениями
- [ ] Настроен `ADMIN_ALLOWLIST` с реальными администраторами
- [ ] `NODE_ENV=production` установлен
- [ ] Проверены все переменные окружения (`npm run check-env`)

### Данные
- [ ] Файлы `topics_easy.json` и `topics_hard.json` заполнены
- [ ] Проверена валидность JSON файлов
- [ ] Создан пустой `state.json` (или выполнен `npm run init-data`)
- [ ] Настроены права доступа к директории `data/`

## 🚀 Развертывание

### Docker (рекомендуется)
- [ ] Dockerfile протестирован локально
- [ ] Docker образ собирается без ошибок
- [ ] `docker-compose.yml` настроен (порты, volumes, env vars)
- [ ] Volumes для данных правильно смонтированы
- [ ] Приложение запускается через `docker-compose up -d`
- [ ] Health check проходит: `curl http://localhost:3000/api/health`

### Nginx (если используется)
- [ ] Nginx установлен и запущен
- [ ] Конфигурация скопирована и проверена (`nginx -t`)
- [ ] Настроены правильные upstream (localhost:3000 или vibe-wheel:3000)
- [ ] Rate limiting настроен
- [ ] Security headers добавлены

### SSL/HTTPS
- [ ] SSL сертификаты получены (Let's Encrypt или другие)
- [ ] Сертификаты скопированы в правильное место (`nginx/ssl/`)
- [ ] HTTPS секция в nginx.conf раскомментирована и настроена
- [ ] Настроен редирект с HTTP на HTTPS
- [ ] Проверено, что HTTPS работает
- [ ] Настроено автообновление сертификатов (certbot renew)

## 🔐 Безопасность

### Доступ
- [ ] SSH доступ только по ключу (пароли отключены)
- [ ] Создан непривилегированный пользователь для приложения
- [ ] Права на файлы минимально необходимые
- [ ] `.env` файл не доступен через веб

### Firewall
- [ ] Открыты только необходимые порты (22, 80, 443)
- [ ] Настроен UFW или iptables
- [ ] Заблокированы неиспользуемые порты
- [ ] Настроено логирование firewall (опционально)

### Приложение
- [ ] `ADMIN_ALLOWLIST` содержит только доверенных пользователей
- [ ] Rate limiting активен (через Nginx)
- [ ] Security headers настроены
- [ ] Отключена X-Powered-By header
- [ ] Логи не содержат чувствительной информации

## 📊 Мониторинг и логирование

### Health Checks
- [ ] `/api/health` endpoint доступен
- [ ] Настроен внешний мониторинг (Uptime Robot, Grafana, или аналог)
- [ ] Настроены алерты при падении сервиса
- [ ] Проверяется каждые 1-5 минут

### Логи
- [ ] Логи приложения пишутся в файлы или stdout
- [ ] Настроена ротация логов (logrotate или Docker logging)
- [ ] Логи доступны для просмотра
- [ ] Логи не занимают слишком много места (max-size, max-file)

### Метрики (опционально)
- [ ] CPU и RAM мониторятся
- [ ] Disk usage отслеживается
- [ ] Response time мониторится
- [ ] Настроены алерты при превышении порогов

## 💾 Резервное копирование

### Автоматическое
- [ ] Настроен cron job для ежедневных бэкапов
- [ ] Бэкапы сохраняются в безопасное место
- [ ] Настроена retention policy (30 дней по умолчанию)
- [ ] Бэкапы тестируются (можно восстановить)

### Ручное
- [ ] Скрипты `backup.sh` / `backup.ps1` доступны и работают
- [ ] Скрипты `restore.sh` / `restore.ps1` протестированы
- [ ] Создан начальный бэкап перед запуском
- [ ] Команда знает, как восстанавливать из бэкапа

## 🧪 Тестирование

### Функциональность
- [ ] Главная страница открывается
- [ ] Пользователь может войти (ввести ФИО)
- [ ] Random тема выдаётся корректно
- [ ] Own идея сохраняется
- [ ] Админ-панель доступна (для администраторов)
- [ ] Админ может модерировать идеи

### Performance
- [ ] Время ответа < 1s для большинства запросов
- [ ] Приложение выдерживает ожидаемую нагрузку
- [ ] Memory leaks отсутствуют (мониторинг в течение нескольких часов)

### Ошибки
- [ ] Проверены логи на наличие ошибок
- [ ] Обработка ошибок работает корректно
- [ ] Health check не показывает проблем

## 📚 Документация

### Для команды
- [ ] Команда знает, где находится сервер
- [ ] Команда знает, как получить доступ
- [ ] Команда знает, как просматривать логи
- [ ] Команда знает, как перезапустить приложение
- [ ] Команда знает, как сделать/восстановить бэкап

### Процессы
- [ ] Описан процесс деплоя обновлений
- [ ] Описан процесс восстановления после сбоя
- [ ] Описан процесс добавления администраторов
- [ ] Описан процесс добавления новых тем

## 🎯 Post-Deployment

### Сразу после деплоя
- [ ] Проверен health check
- [ ] Проверены все основные функции
- [ ] Созданы тестовые пользователи
- [ ] Проверен доступ администраторов
- [ ] Проверены логи (отсутствие ошибок)

### Первые 24 часа
- [ ] Мониторинг показывает стабильную работу
- [ ] Нет критических ошибок в логах
- [ ] Performance в пределах нормы
- [ ] Пользователи не сообщают о проблемах

### Первая неделя
- [ ] Создан первый автоматический бэкап
- [ ] Протестировано восстановление из бэкапа
- [ ] Мониторинг настроен и работает
- [ ] Команда знакома с процессами

## 🔄 Обновления

### Процесс
- [ ] Описан процесс обновления приложения
- [ ] Тестируется на staging перед production
- [ ] Создаётся бэкап перед обновлением
- [ ] Возможен rollback при проблемах

### Регулярное обслуживание
- [ ] Запланированы регулярные обновления ОС
- [ ] Запланированы обновления зависимостей
- [ ] Запланирована проверка бэкапов
- [ ] Запланирована ротация логов

## ✅ Финальная проверка

**Перед запуском на production убедитесь:**

- [ ] Все пункты выше отмечены
- [ ] Команда готова к запуску
- [ ] Есть план на случай проблем
- [ ] Настроены каналы связи для экстренных случаев
- [ ] Документация актуальна

**Приложение готово к production! 🚀**
